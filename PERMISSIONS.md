# AWS Permissions

neboto is **read-only** — it only calls `Describe*` / `List*` / `Get*` style
APIs (plus the explicit opt-in actions noted below). Uses the standard AWS
credential chain (env vars, `~/.aws/credentials`, IAM role). Region comes from
the AWS config or `AWS_DEFAULT_REGION`.

Per-service actions:

- **EC2**: `ec2:DescribeInstances`, `DescribeSecurityGroups`, `DescribeVolumes`, `DescribeSnapshots` (EBS volume Snapshots section + the account-wide Snapshots sub-tab, `owner_ids=self`), `DescribeNetworkInterfaces` (also the SG "Used By" section, filtered by `group-id`), `DescribeImages` (AMIs sub-tab, `owners=self`), `DescribeImageAttribute` (AMI launch permissions), `DescribeLaunchTemplates`, `DescribeLaunchTemplateVersions` (Launch Templates sub-tab), `DescribeAddresses` (Elastic IPs sub-tab), `DescribeInstanceAttribute` (instance User Data section, `Attribute=userData`), `GetConsoleOutput` (instance Console section — the system log, `latest=true` with a plain-call fallback); instance Load Balancing section: `elasticloadbalancing:DescribeTargetGroups`, `elasticloadbalancing:DescribeTargetHealth`, `autoscaling:DescribeAutoScalingGroups` (only for ASG-tagged instances); instance-profile role: `iam:GetInstanceProfile`; SSM Session Manager (`s`): `ssm:DescribeInstanceInformation`, `ssm:StartSession` (also needs the `aws` CLI + `session-manager-plugin` locally)
- **VPC**: `ec2:DescribeVpcs`, `DescribeSubnets`, `DescribeRouteTables`, `DescribeInternetGateways`, `DescribeNatGateways`, `DescribeNetworkAcls`, `DescribeVpcEndpoints`, `DescribeVpnConnections`, `DescribeCustomerGateways`, `DescribeDhcpOptions`, `DescribeVpcPeeringConnections`, `DescribeManagedPrefixLists`, lazy `GetManagedPrefixListEntries` (prefix-list Entries section), `DescribeEgressOnlyInternetGateways`, `DescribeVpnGateways`, lazy `DescribeFlowLogs` (VPC-pane Flow Logs section), lazy `DescribeVpcAttribute` (VPC-pane DNS Support/Hostnames rows); NAT gateway metrics (`m`): `cloudwatch:GetMetricStatistics` (`AWS/NATGateway`, dim `NatGatewayId`); VPN metrics (`m`): `cloudwatch:GetMetricStatistics` (`AWS/VPN`, dim `VpnId`)
- **ECS**: `ecs:ListClusters`, `DescribeClusters`, `ListServices`, `DescribeServices`, `ListTaskDefinitions`, `DescribeTaskDefinition`, `ListTasks`, `DescribeTasks`; task logs (`v`): `logs:GetLogEvents`; live tail (`t`): `logs:FilterLogEvents`; metrics (`m`): `cloudwatch:GetMetricStatistics` (`ECS/ContainerInsights` — requires Container Insights)
- **ECR**: `ecr:DescribeRepositories`, `DescribeImages`, `GetLifecyclePolicy`, `ListTagsForResource`; metrics (`m`): `cloudwatch:GetMetricStatistics` (`AWS/ECR`, dim `RepositoryName`)
- **S3**: `s3:ListAllMyBuckets`, `GetBucketLocation`, `GetBucketTagging`, and the other `s3:GetBucket*` reads (website / replication / CORS / versioning / logging / encryption / policy / lifecycle / notification / ownership / acl, plus `GetBucketPublicAccessBlock`, `GetBucketPolicyStatus` and `GetBucketObjectLockConfiguration`). A denied `GetBucketPublicAccessBlock` renders the bucket's public-access posture as **⚠ Unknown** (never as "public allowed"). **Four more do not match the `s3:GetBucket*` wildcard** — the API is `ListBucket*Configurations` but the IAM action is not: `s3:GetAnalyticsConfiguration`, `s3:GetInventoryConfiguration`, `s3:GetMetricsConfiguration`, `s3:GetIntelligentTieringConfiguration`. Grant them explicitly or the Advanced section's analytics/inventory/metrics/intelligent-tiering counts fail. Object browser (`o`): `s3:ListBucket`, `s3:GetObject` (`ListObjectsV2` + `HeadObject`); versions mode (`V`): `s3:ListBucketVersions`, and reading a specific version (view/download/presign/HEAD) needs `s3:GetObjectVersion` — a separate action `s3:GetObject` does not imply; storage metrics (detail pane + `m` overlay): `cloudwatch:GetMetricData` (`AWS/S3`, summed across every `StorageType` via `SUM(SEARCH(…))`); the bucket pane's File Systems section: `s3files:ListFileSystems` (best-effort — accounts without S3 Files render the error inline in that section only)
- **S3 Files** (`@s3files`): `s3files:ListFileSystems`; lazy sections: `s3files:GetFileSystem` (Details prefix/KMS + Tags), `ListMountTargets` (Mount Targets), `ListAccessPoints` (Access Points, capped), `GetFileSystemPolicy` (Policy — a missing policy 404s and renders as "none", not an error), `GetSynchronizationConfiguration` (Sync). **Never called**: any `Create*`/`Delete*`/`Put*`/`Update*` action. Regional
- **S3 Tables** (`@s3tables`): list load: `s3tables:ListTableBuckets` + per-bucket `s3tables:ListTables`; lazy sections: `s3tables:GetTableBucketEncryption` (Details — a 404 is the SSE-S3 default, not an error) + `s3tables:ListTagsForResource` (Details/Tags, buckets and tables), `s3tables:ListNamespaces` (Namespaces), `s3tables:GetTableBucketMaintenanceConfiguration` / `GetTableMaintenanceConfiguration` + `GetTableMaintenanceJobStatus` (Maintenance — job status is best-effort), `s3tables:GetTableBucketPolicy` / `GetTablePolicy` (Policy — missing 404s render as "none"), `s3tables:GetTable` (table Details). **Never called**: any `Create*`/`Delete*`/`Put*`/`Rename*`/`Update*` action. Regional

- **RDS**: `rds:DescribeDBInstances`, `DescribeDBClusters`, `DescribeDBSnapshots`, `DescribeDBClusterSnapshots` (Snapshots sub-tab, self-owned); `DescribeDBParameterGroups`, `DescribeDBClusterParameterGroups` (Param Groups sub-tab), `DescribeOptionGroups` (Option Groups sub-tab), `DescribeDBSubnetGroups` (Subnet Groups sub-tab); `DescribeDBParameters`, `DescribeDBClusterParameters` (parameter group Parameters section); `DescribePendingMaintenanceActions` (instance/cluster Maintenance section), `DescribeEvents` (instance/cluster Events section); `DescribeDBLogFiles` (instance Logs section), `DownloadDBLogFilePortion` (`e` on a log-file row); metrics (`m`): `cloudwatch:GetMetricStatistics` (`AWS/RDS`, dim `DBInstanceIdentifier` for instances / `DBClusterIdentifier` for clusters); Performance Insights (instance detail Perf Insights section, when enabled): `pi:GetResourceMetrics`; log tail (`t`, on enabled CloudWatch log exports): `logs:FilterLogEvents`
